## 📌 Overview

Large language models (LLMs) are increasingly used in dialogue systems such as assistants, tutors, customer-service applications, and social chatbots. Although their responses often appear natural, they may differ from human conversations in lexical, syntactic, stylistic, and interactional patterns.

This project investigates **which linguistic properties distinguish human-written dialogue from LLM-generated dialogue**, whether these properties can support reliable detection, and whether the observed differences reflect robust conversational behavior rather than dataset-specific artifacts.

The project combines supervised text classification, interpretable linguistic feature analysis, sentiment and cognition analysis, conversational alignment measures, and bias / sensitivity checks.

> **Core principle:** The objective is not simply to achieve the highest classification score. We aim to understand *what* the models detect, *why* the differences occur, and whether they reflect robust conversational behavior rather than dataset-specific artifacts.

## 🔑 Key Findings

- **Detection is easy for ChatGPT (GPT-3.5) dialogues.** Semantic embeddings (DistilBERT, 98.0%) and sentiment/cognition features (SEANCE + Random Forest, F1 98.85%) are the most discriminative approaches.
- **Content-independent features still separate the classes.** Punctuation alone reaches 68.5% accuracy, 21 spaCy grammatical features 77.9%, and 31 stylometric features 90.2%.
- **Length is a major confound.** The number of words per dialogue is the most important SEANCE feature, and the raw repetition gap (15.13% GPT vs 2.55% human) shrinks or even reverses once length is controlled.
- **After removing length-biased features, detection remains possible.** Only ~15 features (VADER, ANEW, Hu-Liu) remain, and still reach ~96% accuracy. `vader_compound` dominates: GPT dialogues are overwhelmingly very positive, while human dialogues are spread across positive and negative values.
- **GPT dialogues align more with their partner.** Adjacent-turn lexical overlap and semantic similarity are higher for GPT, and GPT similarity rises over the course of the conversation (in a curated sample). This does not, by itself, establish adaptation or empathy.

## 🎯 Research Questions

- What basic linguistic and conversational properties differ between human and LLM-generated dialogues?
- Are there systematic lexical, syntactic, stylistic, or interactional differences?
- Do humans and LLMs differ in how they adapt their language to their conversational partner?
- Can linguistic properties distinguish human-written from LLM-generated dialogue?
- Are these differences robust conversational behaviour rather than dataset-specific artifacts?

See [Scope and Limitations](#-scope-and-limitations) for the parts of the original project subject that were not covered.

## 📚 Datasets

| Dataset | Description |
|---|---|
| [EmpatheticDialogues](https://github.com/facebookresearch/EmpatheticDialogues) | Human conversations centered on emotional situations |
| [2GPTEmpathicDialogues](https://github.com/morganlee123/2GPTEmpathicDialogues) | Conversations generated by two independent ChatGPT instances under scenarios corresponding to EmpatheticDialogues |
| `paired_human_llm_dialogues` | Processed dataset containing paired human and LLM-generated dialogues |

The baseline dataset comes from *"A Linguistic Comparison between Human and ChatGPT-Generated Conversations"* (Sandler, Choung, Ross, David — [arXiv:2401.16587](https://arxiv.org/abs/2401.16587)).

The processed dataset uses the following columns:

| Column | Description |
|---|---|
| `conv_id` | Conversation identifier |
| `context` | Emotional or conversational context |
| `prompt` | Initial conversational prompt |
| `human_dialogue` | Human-written dialogue |
| `llm_dialogue` | LLM-generated dialogue |

### Preprocessing

Human and LLM datasets are cleaned and paired by conversation ID:

1. Removal of invalid CSV rows.
2. Check and removal of speaker labels (human dialogues are filtered to exactly two speaker IDs; GPT dialogues must contain both `Assistant1` and `Assistant2`).
3. Formatting standardization: lowercasing, `_comma_` → `,`, removal of spaces before punctuation, collapsing of line breaks / tabs / multiple spaces, trimming, and replacement of missing or non-text values by empty strings.
4. Dialogue reconstruction (human messages joined in their original order).
5. Human / LLM dialogue pairing.

The goal is to prevent the models from relying on dataset-specific artifacts rather than actual linguistic patterns.

### Samples used

| Analysis | Sample |
|---|---|
| Descriptive linguistic features | 17,780 matched pairs (17,779 for word length and contractions, excluding one numeric-only human dialogue) |
| Classifiers | Fixed-length excerpts of **60 consecutive words**, to reduce dialogue-length bias |
| Conversational alignment | 320 matched pairs (640 dialogues) selected from the original 19,533-pair corpus: 10 pairs per emotion, with 1,040 human and 2,155 GPT transitions |

### Bias / data leakage identification

The following sources of bias were reviewed: formatting differences, speaker labels, prompt overlap, duplicate conversations, dialogue length, dataset-specific vocabulary, response patterns, and conversation structure.

## 🔬 Methodology & Results

### 1. Classifiers

All four classifiers use 60-word excerpts, standardized features (z-score) and logistic regression, except DistilBERT's embeddings which are also standardized before the classifier.

| Classifier | Features | Result | Content-dependence |
|---|---|---|---|
| **Vocabulary / BoW** | Word frequencies (simple baseline) | — | Highly dependent on vocabulary and topics |
| **DistilBERT** | 768-d `[CLS]` embeddings + z-score + Logistic Regression | **98.0%** accuracy | Still relies on vocabulary and content |
| **Sentence-BERT** | 384-d `all-MiniLM-L6-v2` embeddings + neural network (70/15/15 split) | Validation macro-F1 ≈ 0.99 | Still relies on vocabulary and content |
| **Punctuation** | 8 punctuation frequencies (per 100 words) | **68.5%** accuracy | Shift towards less content-dependent features |
| **Stylometric** | 31 features: word length, lexical diversity, repetition, punctuation density, repeated letters, capitalization, sentence-like segment length… | **90.2%** accuracy | Even less content-dependent |
| **spaCy (linguistic)** | 21 features: 12 POS + 9 dependency (DEP) proportions | **77.9%** accuracy | Even less content-dependent |

For spaCy features, removing only 3 features decreases the F1-score by about 10%.

### 2. Descriptive linguistic comparison (full dialogues)

| Feature | Human | GPT | Paired dz |
|---|---:|---:|---:|
| Mean word length (characters) | 3.840 | 4.496 | +1.924 |
| Contractions per 100 words | 2.595 | 4.724 | +0.706 |
| Question marks per 100 words | 1.853 | 1.134 | −0.347 |
| Mean dependency-tree depth | 4.061 | 5.037 | +0.929 |
| Within-dialogue depth SD | 1.429 | 1.876 | +0.702 |

GPT dialogues use longer words and deeper syntax. These descriptive differences depend on text length and parsing conventions, and describe differences between sources rather than syntactic adaptation between interlocutors.

Part-of-speech distributions show that LLM dialogues are more regular (narrower distributions for ADV, AUX, ADJ, ADP, DET, PRON, VERB, PUNCT), while human dialogues are more variable and include many more texts with no CCONJ, SCONJ or PART.

### 3. Sentiment and cognition analysis (SEANCE)

[SEANCE](https://doi.org/10.3758/s13428-016-0743-z) (SEntiment Analysis and Cognition Engine, Crossley et al., 2017) is an open-source tool that turns texts into **250 core sentiment and cognition indices**, drawn from eight lexicons (Harvard IV-4 / General Inquirer: 119, Lasswell: 63, GALC: 38, NRC EmoLex: 10, ANEW: 6, SenticNet: 5, Hu-Liu: 5, VADER: 4).

- **Classifier:** Random Forest (100 trees, 5-fold, 80% train / 20% test).
- **Result with all 250 features:** F1 ≈ **98.85%** (3518/3556 humans and 3515/3556 machines correctly classified).
- **Most important features:** `nwords` (by far), `vader_compound`, `Indadj_GI`, `Self_GI`, `Rcgain_Lasswell`, `Perceiv_GI`, `Affgain_Lasswell`, `Powends_Lasswell`, `Meanslw_Lasswell`, `Eval_2_GI`.
- **Observations:** human `vader_compound` is spread fairly evenly across positive and negative emotions, while GPT is strongly concentrated near +1. Human dialogues have higher `Self_GI` (self-focused lexicon), and GPT uses more evaluative/subjective adjectives (`Indadj_GI`).

**Thematic ablation.** The top 5 features are removed iteratively and the model retrained, as long as F1 stays above 90%. Counting removed features per category:

- Categories with the most removed features: *Dominance, respect, money and power*, *Positive emotion words*, *Cognition* (to be interpreted with caution: features are not evenly distributed across categories).
- Categories reduced fastest at the beginning: *Other affect*, *Reference*, *Action*.

**Word-count bias.** Several lexicons give occurrence rates that strongly correlate with dialogue length (General Inquirer, GALC, NRC EmoLex, Lasswell). ANEW is weakly linked to length, VADER is independent of length, and Hu-Liu is weakly linked once `hu_liu_pos_nwords` / `hu_liu_neg_nwords` are dropped. Removing the length-biased features leaves **~15 features** (VADER, ANEW, Hu-Liu) which still reach **~96% accuracy** (3445/3556 humans, 3383/3556 machines). `vader_compound` clearly dominates importance, followed by `hu_liu_prop`, `hu_liu_pos_perc` and `hu_liu_neg_perc`.

### 4. Conversational alignment

Alignment is measured between **adjacent contributions** (a transition links two consecutive utterances) on the 320-pair curated sample. Scores are averaged per conversation so each dialogue has the same weight.

- **Lexical overlap:** Jaccard index on lowercase words (no function-word removal).
- **Semantic similarity:** cosine similarity between `all-MiniLM-L6-v2` embeddings (no fine-tuning).

| Full-dialogue measure | Human | GPT | Gap and 95% bootstrap CI |
|---|---:|---:|---|
| Lexical overlap | 0.0602 | 0.1558 | +0.0956 [0.0883, 0.1028] |
| Semantic similarity | 0.3100 | 0.5940 | +0.2840 [0.2678, 0.3008] |

Confidence intervals use 10,000 bootstrap resamples of matched pairs (conditional on the selected sample).

**Sensitivity check — first three transitions only** (all 320 pairs retained):

| Measure | Human | GPT | GPT higher |
|---|---:|---:|---:|
| Lexical overlap | 0.0606 | 0.1309 | 261/320 (81.6%) |
| Semantic similarity | 0.3100 | 0.5601 | 290/320 (90.6%) |

**Progression:** GPT similarity rises from early to late stages of the conversation, while human similarity stays flat (lexical) or decreases slightly (semantic).

**Interpretation:** similarity alone does not establish partner adaptation or empathy; it may reflect thematic continuity or repetition.

### 5. Sensitivity of repetition to length

| Setting | Human | GPT |
|---|---:|---:|
| Raw bigram repetition (17,779 pairs) | 2.55% | 15.13% |
| Pairwise-minimum window (same 15,546 pairs, 10 windows/dialogue) | 2.67% | 2.75% |
| Fixed 30-bigram window (same 15,546 pairs, 10 windows/dialogue) | 1.50% | 0.99% |

The repetition gap shrinks or reverses under length controls. Since raw and controlled populations differ, this is a **sensitivity diagnostic**, not a causal estimate of length effects.

## ⚠️ Scope and Limitations

- **Single LLM:** the analysis is based on one model (ChatGPT / GPT-3.5); generalization to other LLMs has not been tested.
- **Length remains a confound:** descriptive differences depend on text length and parsing conventions; utterance word length is uncontrolled in the alignment analysis.
- **Curated alignment sample:** 320 pairs balanced by emotion, not a random sample of the corpus; unequal contribution lengths; both GPT participants are generated.
- **Missing data:** 31 human dialogues have 50 missing utterances; their impact on classifier performance has not been quantified.
- **Not covered:** Language Style Matching (LSM), combined classifier (text + linguistic features), classifier re-evaluation on paraphrased/transformed text, and a systematic error analysis.

## 🚀 Going Further

- **Data processing:** normalize dialogue length.
- **Conversational alignment:** use Linguistic Style Matching to obtain stronger evidence of empathy.
- **Generalization:** other types of text; other LLMs.

## 🛠️ Installation and Usage

The repository includes a Sentence-BERT + neural network classification pipeline.

### Requirements

- Python 3.10 or a compatible Python version
- pip
- Internet access for downloading the pretrained Sentence-BERT model on first use
- CPU or a compatible CUDA-enabled GPU

### 1. Install dependencies

From the repository root:

```bash
pip install pandas numpy scikit-learn sentence-transformers torch matplotlib seaborn joblib
```

These dependencies provide:

- **pandas / NumPy:** data manipulation and numerical operations
- **Sentence-Transformers:** pretrained Sentence-BERT embeddings
- **PyTorch:** neural network implementation and training
- **scikit-learn:** dataset splitting and evaluation metrics
- **Matplotlib / Seaborn:** plots and confusion matrix
- **joblib:** configuration serialization

Other analyses (spaCy features, DistilBERT, SEANCE) may require additional packages such as `spacy` (with an English model) and `transformers`.

### 2. Prepare the dataset

Place the processed CSV file at:

```text
data/processed/paired_human_llm_dialogues.csv
```

The CSV must contain the following columns:

```text
conv_id, context, prompt, human_dialogue, llm_dialogue
```

The classifier requires `conv_id`, `human_dialogue`, and `llm_dialogue`. The additional columns can be retained for other experiments.

### 3. Run the classifier

From the repository root:

```bash
python src/human_or_machine/train_classifier.py
```

To specify a different dataset path:

```bash
python src/human_or_machine/train_classifier.py \
    --data data/processed/your_dataset.csv
```

The script automatically selects CUDA when a CUDA-enabled GPU is available; otherwise, it runs on CPU. On the first run, the pretrained Sentence-BERT encoder is downloaded if it is not already available locally.

### 4. Outputs

```text
models/
└── human_or_machine/
    ├── sentence_bert/
    ├── classifier.pt
    └── config.joblib

reports/
```

| `training_curves.png` | Training and validation learning curves |

### Sentence-BERT classifier details

Each row of the paired dataset produces two labeled examples (`0` = human, `1` = LLM). The split is done with `GroupShuffleSplit` on `conv_id` (70% train / 15% validation / 15% test) so that dialogues from the same conversation stay in the same subset.

The encoder (`sentence-transformers/all-MiniLM-L6-v2`, 384 dimensions) is pretrained and **not fine-tuned**; only the PyTorch classifier is trained:

| Component | Configuration |
|---|---|
| Architecture | 384 → 256 (ReLU, dropout 0.3) → 64 (ReLU, dropout 0.3) → 2 |
| Optimizer | AdamW (lr 0.001, weight decay 0.0001) |
| Batch size / max epochs | 32 / 30 |
| Early stopping | Patience of 5 epochs on validation macro-F1 |
| Loss / seed | Cross-entropy / 42 |

Reported metrics: accuracy, precision, recall, macro-F1 and confusion matrix.
