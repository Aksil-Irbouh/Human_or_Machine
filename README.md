## 📌 Overview

Large language models (LLMs) are increasingly used in dialogue systems such as assistants, tutors, customer-service applications, and social chatbots. Although their responses often appear natural, they may differ from human conversations in lexical, syntactic, stylistic, and interactional patterns.

This project investigates **which linguistic properties distinguish human-written dialogue from LLM-generated dialogue**, whether these properties can support reliable detection, and whether the observed differences remain robust after superficial text transformations.

The project combines supervised text classification, interpretable linguistic feature analysis, conversational alignment measures, and robustness experiments.

> **Core principle:** The objective is not simply to achieve the highest classification score. We aim to understand *what* the models detect, *why* the differences occur, and whether they reflect robust conversational behavior rather than dataset-specific artifacts.

## 🎯 Research Questions

We will investigate:

- What basic linguistic and conversational properties differ between human and LLM-generated dialogues?
- Are there systematic lexical, syntactic, stylistic, or interactional differences?
- Do humans and LLMs differ in how they adapt their language to their conversational partner?
- Can linguistic properties distinguish human-written from LLM-generated dialogue?
- Do interpretable linguistic features improve on a text-only baseline?
- Do observed differences remain after meaning-preserving text transformations?
- Do patterns learned from one LLM generalize to dialogue generated by another LLM?

Before conducting further experiments, we will perform exploratory data analysis covering:

- Number of dialogues and conversations

- Representative examples

## 🔬 Methodology

### 1. Exploratory Data Analysis

We will inspect both corpora to identify structural and stylistic differences that could make classification artificially easy.

Potential confounding factors include:

- Systematically longer LLM responses
- More regular conversation lengths
- Distinct punctuation or capitalization conventions
- Expressions that appear predominantly in one corpus
- Formatting or preprocessing differences

### 2. Linguistic Feature Analysis

We will select a focused set of features from at least three linguistic levels.

| Level | Candidate features |
|---|---|
| Lexical | Turn length, sentence length, lexical diversity, repetition, contractions, vocabulary overlap |
| Syntactic | Part-of-speech distributions, dependency-tree depth, dependency distance, clause density |
| Stylistic / Pragmatic | Questions, hedging, intensifiers, politeness, formality, punctuation, acknowledgements, sentiment |

For each selected feature, we will:

1. Define how the feature is calculated.
2. Calculate it for each dialogue.
3. Compare its distribution across the two classes.
4. Quantify the magnitude of the observed difference.
5. Interpret what the difference may reveal about conversational behavior.

### 3. Conversational Alignment

Human conversational partners often adapt their language to one another. This phenomenon is commonly called **linguistic accommodation** or **alignment**.

We will implement at least one alignment measure, such as:

- Language Style Matching (LSM)
- Lexical overlap between consecutive turns
- Semantic similarity between consecutive turns
- Similarity in utterance length
- Syntactic alignment
- Emotional alignment

We will compare alignment distributions and examine whether alignment:

- Differs between human-human and LLM-generated conversations
- Changes as the conversation progresses
- Is consistent throughout a dialogue
- Produces similar conclusions across stylistic and semantic measures

### 4. LLM-Generated Dialogue Detection

We have implemented an initial supervised classification pipeline using **Sentence-BERT embeddings and a neural network classifier**.

The implementation serves as the first text-based baseline for subsequent comparisons with interpretable linguistic features and combined models.

#### 4.1. Current model architecture

The pipeline consists of the following stages:

1. Load the paired dialogue dataset.
2. Convert the human and LLM dialogue columns into individual labeled examples.
3. Split the data into training, validation, and test subsets.
4. Encode each dialogue using a pretrained Sentence-BERT model.
5. Train a feed-forward neural network on the resulting embeddings.
6. Evaluate the classifier on the held-out test set.
7. Save the trained model, predictions, metrics, and plots.

#### 4.2. Data preparation

Each row of the paired dataset produces two labeled examples:

| Text source | Label | Meaning |
|---|---:|---|
| `human_dialogue` | 0 | Human-written dialogue |
| `llm_dialogue` | 1 | LLM-generated dialogue |

The resulting classification task is binary:

- `0` → `human`
- `1` → `llm`

To reduce data leakage, the implementation uses `GroupShuffleSplit` with `conv_id` as the grouping variable. Dialogues originating from the same conversation remain in the same subset.

The target proportions are approximately:

| Subset | Target proportion | Purpose |
|---|---:|---|
| Training | 70% | Learn classifier parameters |
| Validation | 15% | Monitor performance and select the best checkpoint |
| Test | 15% | Estimate final generalization performance |

Actual proportions may vary because the split is performed by conversation groups.

#### 4.3. Sentence-BERT embeddings

The current implementation uses:

`sentence-transformers/all-MiniLM-L6-v2`

Sentence-BERT transforms each dialogue into a dense vector representation with 384 dimensions.

These embeddings capture semantic and contextual information and are used as input to the downstream classifier.

The encoder is pretrained and **is not fine-tuned on the dialogue classification task** in the current implementation. Only the neural network classifier is trained.

#### 4.4. Neural network classifier

The classifier is implemented in PyTorch and uses the following architecture:

| Layer | Configuration |
|---|---|
| Input | 384-dimensional Sentence-BERT embedding |
| Hidden layer 1 | 256 units + ReLU |
| Regularization | Dropout = 0.3 |
| Hidden layer 2 | 64 units + ReLU |
| Regularization | Dropout = 0.3 |
| Output | 2 class scores |

Training configuration:

| Parameter | Value |
|---|---|
| Optimizer | AdamW |
| Learning rate | 0.001 |
| Weight decay | 0.0001 |
| Batch size | 32 |
| Maximum epochs | 30 |
| Early stopping patience | 5 epochs |
| Random seed | 42 |
| Loss function | Cross-entropy |

Early stopping monitors validation macro-F1 and retains the model state that achieves the best validation score.

#### 4.5. Planned model comparison

The Sentence-BERT classifier is the first model in a broader comparison.

| Model | Input | Status |
|---|---|---|
| Sentence-BERT + neural classifier | Pretrained text embeddings | Implemented |
| Linguistic-feature classifier | Interpretable linguistic and conversational features | Planned |
| Combined classifier | Text embeddings + linguistic features | Planned |
| Fine-tuned Transformer | Dialogue text with supervised Transformer fine-tuning | Planned |

We will compare model performance and investigate which linguistic signals contribute to classification.

#### 4.6. Evaluation metrics

The implementation reports:

- Accuracy
- Precision
- Recall
- Macro-F1
- Confusion matrix

Macro-F1 gives equal weight to both classes when averaging their F1-scores. This helps assess performance on both human-written and LLM-generated dialogue.

Beyond predictive performance, we will analyze misclassified examples, potential confounding factors, and whether the classifier learns robust characteristics or dataset-specific shortcuts.

### 5. Robustness Analysis

To determine whether the classifier relies on superficial properties, we will create at least one meaning-preserving modified version of the evaluation data.

Potential transformations include:

- Punctuation and capitalization normalization
- Spelling correction
- Contraction normalization
- Utterance-length control
- Language-model paraphrasing

**Important:** Any transformation must be applied using the same procedure to both human and LLM-generated dialogue. Otherwise, the transformation process itself may introduce a class-specific signal.

We will compare:

- Classification performance before and after transformation
- Linguistic differences before and after transformation
- Features that remain stable
- Features that disappear
- What performance changes imply about the original classifier

### 6. Error Analysis & Hypotheses

We will inspect conversations that:

- Were incorrectly classified
- Changed classification after transformation
- Received different predictions from text-based and linguistic-feature models
- Contain recurring phenomena such as unusually long responses, follow-up questions, politeness, or formality

Based on these observations, we will formulate **2–3 hypotheses** explaining why human and LLM conversations can or cannot be distinguished.

## 🛠️ Installation and Usage

### Requirements

- Python 3.10 or a compatible Python version
- pip
- Internet access for downloading the pretrained Sentence-BERT model on first use
- CPU or a compatible CUDA-enabled GPU

### 1. Install dependencies

From the repository root:

```bash
pip install pandas numpy scikit-learn sentence-transformers torch matplotlib seaborn joblib
```

These dependencies provide:

- **pandas / NumPy:** data manipulation and numerical operations
- **Sentence-Transformers:** pretrained Sentence-BERT embeddings
- **PyTorch:** neural network implementation and training
- **scikit-learn:** dataset splitting and evaluation metrics
- **Matplotlib / Seaborn:** plots and confusion matrix
- **joblib:** configuration serialization

### 2. Prepare the dataset

Place the processed CSV file at:

```text
data/processed/paired_human_llm_dialogues.csv
```

The CSV must contain the following columns:

```text
conv_id, context, prompt, human_dialogue, llm_dialogue
```

The current implementation requires `conv_id`, `human_dialogue`, and `llm_dialogue`. The additional columns can be retained for other experiments.

### 3. Run the classifier

From the repository root:

```bash
python src/human_or_machine/train_classifier.py
```

To specify a different dataset path:

```bash
python src/human_or_machine/train_classifier.py \
    --data data/processed/your_dataset.csv
```

The script automatically selects CUDA when a CUDA-enabled GPU is available; otherwise, it runs on CPU.

On the first run, the pretrained Sentence-BERT encoder is downloaded if it is not already available locally.

### 4. Outputs

The script creates the following directories and files:

```text
models/
└── human_or_machine/
    ├── sentence_bert/
    ├── classifier.pt
    └── config.joblib

reports/
└── human_or_machine/
    ├── test_metrics.json
    ├── test_predictions.csv
    ├── training_history.csv
    ├── confusion_matrix.png
    └── training_curves.png
```

| Output | Description |
|---|---|
| `sentence_bert/` | Saved Sentence-BERT encoder |
| `classifier.pt` | Trained neural network weights and architecture metadata |
| `config.joblib` | Model configuration and label mapping |
| `test_metrics.json` | Accuracy, macro-F1, classification report, and confusion matrix |
| `test_predictions.csv` | Test examples, true labels, predictions, and class probabilities |
| `training_history.csv` | Training and validation loss and validation macro-F1 per epoch |
| `confusion_matrix.png` | Visualization of classification errors |
| `training_curves.png` | Training and validation learning curves |

The reported test metrics are generated from the held-out test subset. No performance values are claimed here before running the experiment.

## 📊 Evaluation Principles

We will prioritize:

- **Interpretability:** Explain which linguistic properties drive observed differences.
- **Robustness:** Test whether findings survive meaning-preserving transformations.
- **Fair comparison:** Apply preprocessing and transformations consistently across classes.
- **Reproducibility:** Keep data preparation, feature extraction, and experiments documented.
- **Scientific caution:** Treat unexpected or negative results as valuable findings.
- **Generalization:** Consider whether patterns extend beyond a single dataset or model.
- **Leakage prevention:** Keep paired conversations within the same data split.
- **Transparent reporting:** Report actual experimental results and acknowledge limitations.
